2.1 TEACHER Access Flow
ครั้งแรกกรอก FirstName และ LastName ระบบค้นหา StaffDB ด้วยค่าที่ปรับรูปแบบแล้ว หากพบหนึ่งรายการให้แสดงข้อมูลยืนยันแบบปิดบางส่วนก่อนเปิดสิทธิ์ หากชื่อซ้ำให้ตรวจ Phone เพิ่มเติม
หาก Phone ที่กรอกไม่ตรง StaffDB ให้แจ้งว่าข้อมูลอาจเปลี่ยน ห้ามแก้ StaffDB อัตโนมัติ และสร้างคำขอตรวจสอบข้อมูลให้ ADMIN/HEALTH ก่อนใช้เบอร์ใหม่เป็นข้อมูลยืนยัน
ระบบต้องตรวจ RoleKey = TEACHER, LoginEnabled = TRUE, RecordStatus = ACTIVE และไม่ถูกระงับ ก่อนสร้าง Trusted Device
ไม่ใช้ QR และไม่ให้ TEACHER สร้าง PIN/Password อนุญาต Trusted Device ที่ Active ได้หนึ่งอุปกรณ์ต่อ StaffID และให้ยืนยันใหม่เมื่อหมดอายุ เปลี่ยนอุปกรณ์ หรือล้างข้อมูล Browser
ก่อนเปิดข้อมูลทุก Session ให้เลือก Access Context เพียง 3 ค่า: CLASSROOM (ครูประจำชั้น/ห้องเรียน), DUTY (ครูเวร/สถานที่และช่วงเวร) หรือ DORM (ครูหอนอน/หอนอน)
ระบบสร้าง RequestID และบันทึก StaffID, RoleKey, Access Context, Scope ที่กรอก, เวลา, StudentID และ Resource ที่เปิดใน LogDB
TEACHER เป็น Read-only ทุก Resource ห้าม Create, Update, Cancel และ Export ข้อมูลดิบ
แผนยาปัจจุบันเปิดดูได้โดยไม่ใช้ Break-glass และไม่ผูกครูไว้กับประเภทหน้าที่ถาวร โดยส่งไป Browser เฉพาะ MedicineName, Strength, Dose, เวลาใช้ยา, Route และ Precaution ของ PlanStatus = ACTIVE และ RecordStatus = ACTIVE
เลขบัตรประชาชนแสดงแบบปิดบางส่วนตามปกติ การเปิดเลขเต็มต้องผ่าน NationalID Break-glass ตามข้อ 2.3
2.2 EXECUTIVE Access Flow
ครั้งแรกตรวจ FirstName/LastName และใช้ Phone เมื่อชื่อซ้ำตามกติกาเดียวกับ TEACHER จากนั้นตรวจ RoleKey = EXECUTIVE, LoginEnabled = TRUE และ RecordStatus = ACTIVE ก่อนสร้าง Trusted Device
EXECUTIVE เปิดได้เฉพาะรายงานเพื่อการตัดสินใจแบบ Read-only ระบบบันทึกการเปิดรายงานใน LogDB ทุกครั้ง ห้ามมีปุ่ม Create, Update, Cancel, Export ข้อมูลดิบ หรือปรับโครงสร้างระบบ
2.3 NationalID Break-glass และ External Medical Request
เลขบัตรประชาชนแสดงแบบปิดบางส่วนเป็นค่าเริ่มต้น การเปิดเลขเต็มต้องเลือกเหตุผลฉุกเฉินและยืนยัน Break-glass ทุกครั้ง โดยไม่รออนุมัติล่วงหน้าเมื่อจำเป็นต่อการดูแลหรือนำส่งสถานพยาบาล
เมื่อบุคลากรทางการแพทย์ภายนอกขอข้อมูล ผู้เปิดเผยต้องกรอกชื่อผู้ขอ ตำแหน่ง/วิชาชีพ หน่วยงานหรือสถานพยาบาล เบอร์ติดต่อ วัตถุประสงค์ ข้อมูลที่ขอ ความเร่งด่วน และเลขอ้างอิงเอกสารถ้ามี
บุคลากรภายนอกไม่มีบัญชีและไม่เข้าระบบโดยตรง ระบบเปิดหรือส่งออกเฉพาะข้อมูลจำเป็น พร้อม StaffID ผู้เปิดเผย, ผู้รับ, หน่วยงาน, วันเวลา และ RequestID
คำขอปกติให้ HEALTH ตรวจสอบก่อนเปิดเผย ส่วนเหตุฉุกเฉินใช้ Break-glass และแจ้ง HEALTH ตรวจสอบย้อนหลัง
ข้อควบคุมความเสี่ยง
First-use Staff Verification เป็นมติทางธุรกิจและไม่เทียบเท่า PIN/OTP ผู้พัฒนาต้องลดความเสี่ยงด้วย Trusted Device revocation, Read-only API, rate limit, generic error, RequestID, Audit, session timeout, field mask และห้ามส่งข้อมูลเกิน PermissionDB
2.4 Session, Lockout, Device Change และ Emergency Access
Trusted Device มีอายุตามภาคเรียน โดยหมดอายุตาม TermEndDate ที่กำหนดใน ConfigDB และต้องยืนยันใหม่เมื่อเริ่มภาคเรียนถัดไป
Session เมื่อเปิดระบบมีอายุสูงสุด 30 นาที และออกจากระบบเมื่อไม่มีกิจกรรมต่อเนื่อง 15 นาที ค่าใดถึงก่อนให้ใช้ค่านั้น
กรอกข้อมูลยืนยันผิดครบ 5 ครั้งให้ระงับการยืนยันปกติ 15 นาที ใช้ข้อความผิดพลาดแบบไม่เปิดเผยว่าฟิลด์ใดถูกหรือผิด
ระหว่างถูกระงับให้มีปุ่ม Emergency Access แยกจากการเข้าสู่ระบบปกติ ปุ่มนี้ไม่ปลดล็อกบัญชีและเปิดได้เฉพาะข้อมูลฉุกเฉินขั้นต่ำ หลังกรอกชื่อผู้ใช้ Access Context นักเรียน เหตุผล และข้อมูลผู้รับภายนอกเมื่อเกี่ยวข้อง พร้อมบันทึก BREAK_GLASS_ACCESS และส่งอีเมลแจ้งเตือนทันที
Emergency Access จากอุปกรณ์ใหม่ที่ยังไม่ผ่าน Trusted Device อนุญาตให้เปิดเลขบัตรประชาชนเต็มได้ตามมติความเสี่ยงที่ยอมรับ แต่ต้องสร้าง Emergency Session อายุไม่เกิน 5 นาที จำกัด StudentID เดียวต่อ Request ห้าม Browse/Export รายชื่อนักเรียน และต้องบันทึก/แจ้งเตือนทุกครั้ง
การเปลี่ยนอุปกรณ์ให้สุ่มถาม 2 รายการจาก LastName, Phone และ Email แล้วตรวจเทียบ StaffDB การตอบถูกต้องต้องเพิกถอน Trusted Device เดิมก่อนสร้างอุปกรณ์ใหม่
หากข้อมูล Phone หรือ Email เปลี่ยน ให้แสดงข้อมูลเดิมแบบปิดบางส่วนและสร้างคำขอแก้ไขให้ ADMIN/HEALTH ห้ามผู้ใช้แทนค่าข้อมูลยืนยันเองโดยไม่ผ่านการตรวจสอบ
TEACHER และ EXECUTIVE สามารถดูและเพิกถอน Trusted Device ปัจจุบันของตนเองได้ ADMIN มีหน้าจอดูอุปกรณ์ปัจจุบัน เพิกถอน ระงับสิทธิ์ และปรับ RoleKey/Assignment ของครูโดยต้องบันทึก BeforeJSON, AfterJSON และ ChangeReason

4.1 Naming Convention
ชื่อชีตและฟิลด์ใช้ English PascalCase ตาม Data Dictionary เท่านั้น
Primary Key ลงท้าย ID และอยู่คอลัมน์แรก
วันเวลาใช้ ISO 8601 พร้อม Asia/Bangkok; วันที่ล้วนใช้ YYYY-MM-DD
สถานะ Soft delete ใช้ RecordStatus = ACTIVE, CANCELLED หรือ INVALID
ทุกชีตธุรกรรมมี CreatedAt, CreatedBy, UpdatedAt, UpdatedBy, RowVersion และ Note
RowVersion ต้องเพิ่มทีละ 1 เมื่อ Update เพื่อป้องกัน Lost Update

5. StaffDB และความปลอดภัยบัญชี
StaffDB รองรับ Username + PIN/Password + Email OTP สำหรับ ADMIN และ HEALTH โดยตรง ส่วน TEACHER/EXECUTIVE ใช้ FirstName, LastName, Phone และ Email สำหรับ First-use Staff Verification/Device Change และใช้ Trusted Device โดยไม่ใช้ QR และไม่สร้าง PIN
LoginEnabled = TRUE หมายถึงบุคลากรได้รับอนุญาตให้เข้าใช้ตาม Access Flow ของ RoleKey; LoginEnabled = FALSE ต้องปฏิเสธทั้ง Credential Login และ Trusted Device
PIN/Password ต้องเก็บเฉพาะ PINHash + PINSalt; ห้ามเก็บค่าเดิม
ADMIN และ HEALTH ต้องมี Email ที่ตรวจสอบแล้วจึงเปิด LoginEnabled ได้ ระบบส่ง OTP ไปยัง Email ใน StaffDB หลัง Username + PIN/Password ผ่าน และต้องตรวจ OTP สำเร็จก่อนสร้าง Session
OTP มีอายุ 10 นาที ส่งใหม่ได้หลัง 60 วินาที และส่งได้ไม่เกิน 3 ครั้งต่อ StaffID/Request ภายใน 15 นาที OTP ใช้ได้ครั้งเดียวและต้องถูกทำลายเมื่อยืนยันสำเร็จ หมดอายุ หรือมีการออก OTP ใหม่
FailedLoginCount ระงับเมื่อผิดครบ 5 ครั้ง และ LockedUntil กำหนด 15 นาที ใช้กับ Credential Login, Staff Verification, Device Change และ OTP ตาม Request/Staff ที่เกี่ยวข้อง
LastLoginAt บันทึกเมื่อ Credential Login หรือ First-use Staff Verification สำเร็จ
Username ต้อง Unique และ RoleKey ต้องมีใน RoleDB
การเปลี่ยน RoleKey, LoginEnabled หรือปลดล็อกบัญชีต้องบันทึก BeforeJSON/AfterJSON/ChangeReason
TEACHER/EXECUTIVE ใช้ PINHash + PINSalt เก็บ hash/salt ของ Trusted Device token ตาม Role-specific contract โดยห้ามเก็บ token จริง อนุญาตหนึ่งอุปกรณ์ต่อ StaffID มีอายุถึง TermEndDate และอุปกรณ์ใหม่ต้องแทนอุปกรณ์เดิม ห้ามเก็บข้อมูลสุขภาพหรือเลขบัตรไว้ใน localStorage
5.1 Email Notification Contract
อีเมลแจ้งเตือนทุกเหตุการณ์ด้านสิทธิ์และความปลอดภัยส่งถึง Email ของ StaffDB ทุกคนที่ RoleKey = ADMIN หรือ HEALTH, LoginEnabled = TRUE และ RecordStatus = ACTIVE
ผู้ส่งต้องเป็นอีเมลงานอนามัยที่กำหนดในระบบ Production; ห้ามฝังรหัสผ่านอีเมลใน Source Code หรือ Google Sheet
เหตุการณ์ขั้นต่ำที่ต้องแจ้ง: BREAK_GLASS_ACCESS, EXTERNAL_DATA_REQUEST, LOCKOUT, TRUSTED_DEVICE_ENROLLED, TRUSTED_DEVICE_REVOKED, STAFF_DATA_CHANGE_REQUEST และ NationalID full reveal
เนื้อหาอีเมลแจ้งเตือนมีเฉพาะ Event, StaffID, StudentID, EventAt และ RequestID ห้ามใส่เลขบัตรประชาชนเต็ม ชื่อยา ขนาดยา ข้อควรระวัง รายละเอียดสุขภาพ หรือ BeforeJSON/AfterJSON
การส่งอีเมลล้มเหลวต้องบันทึก SYSTEM_ERROR และคิวให้ ADMIN/HEALTH เห็นในระบบ แต่ห้ามย้อนยกเลิกการช่วยเหลือฉุกเฉินที่เสร็จแล้ว
